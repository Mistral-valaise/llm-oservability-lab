# Architecture and decisions

## Goals

1. Show production-grade OpenTelemetry instrumentation of a modern workload (an LLM gateway).
2. Run the full stack with one command, locally and in a namespace without cluster-admin.
3. Make security visible: mTLS, network isolation, least privilege, supply chain, and security signals as telemetry.

## Data flow

1. `loadgen` and clients call `ai-gateway` (`POST /v1/chat/completions`, OpenAI-compatible).
2. The gateway authenticates the tenant (API key, constant-time compare), applies a per-tenant token bucket, runs guardrails (size, prompt-injection heuristics) and redacts PII before anything leaves the pod.
3. The provider call is wrapped in a `chat <model>` CLIENT span with GenAI attributes. Token usage, duration and cost are recorded as metrics with exemplars.
4. All three signals go over OTLP/gRPC with mutual TLS to the collector.
5. The collector limits memory, adds the environment, scrubs secrets and prompt content, batches, and fans out: traces to Tempo, metrics to Prometheus's OTLP receiver, logs to Loki's OTLP endpoint.
6. Tempo's metrics-generator remote-writes service-graph and span metrics to Prometheus.
7. Grafana is provisioned with correlated datasources and the dashboard from Git.

## Decisions

| Decision | Why | Trade-off |
| --- | --- | --- |
| Push metrics via OTLP into Prometheus instead of scraping | No Kubernetes service discovery, so no ClusterRole; works in the Sandbox | Prometheus cannot detect a dead target with `up`; we alert on missing data and collector export failures instead |
| Single-binary Loki and Tempo on PVCs | Fits a laptop and the Sandbox quota | Not highly available; production would use object storage and the distributed modes |
| Certificates generated by Helm (`genCA`) and kept with `lookup` | No cert-manager CRDs needed | No automatic rotation; `helm template` shows new certs on every render. cert-manager is the production answer |
| Gateway owns its NetworkPolicy, platform owns default-deny and backend policies | The app team can change its own egress (e.g. to an LLM API) without touching the platform | Two places to look; `kubectl get netpol` shows both |
| Mock LLM provider by default | The demo needs no API key and no GPU, and failures are controllable (`make chaos`) | Token counts are estimated (4 characters per token) |
| In-process rate limiter | Simple and observable | Per pod; keep one replica until a shared store (Redis) exists |
| Helmfile as the entry point | Environments, pinned versions, component switches and ordering in one file | One more CLI; Argo CD integration is the next step (see roadmap) |

## Security model

- **Identity of telemetry senders:** only pods with the client certificate from `otel-client-tls` can send OTLP. The CA key is never stored.
- **Network:** `default-deny-all` plus one policy per component. DNS is the only implicit egress.
- **Pods:** non-root, no privilege escalation, read-only root filesystem, all capabilities dropped, `RuntimeDefault` seccomp, no service-account token mounted. The k3d namespace enforces Pod Security Standard `restricted`.
- **Data:** prompts are never logged; PII is redacted before the upstream call; the collector deletes `authorization` headers and `gen_ai.*.messages` attributes.
- **Supply chain:** pinned chart versions, pinned Python dependencies, multi-arch image with SBOM and SLSA provenance, keyless Cosign signature, vulnerability scan that fails on fixable critical CVEs.
- **Policy as code:** `scripts/check_manifests.py` fails CI if our workloads are not hardened or if the Sandbox render contains cluster-scoped objects or fixed UIDs.

## Roadmap

1. Argo CD: render manifests per environment in CI (rendered-manifests pattern) and let Argo CD sync them on k3d.
2. Streaming responses with time-to-first-token metrics.
3. Redis-backed rate limiter and HPA on request rate.
4. cert-manager option for certificate rotation.
5. Security observability: Kubernetes audit logs, Falco or RHACS events and Cosign verification results in the same Grafana.
6. Elasticsearch as an optional log backend next to Loki.
